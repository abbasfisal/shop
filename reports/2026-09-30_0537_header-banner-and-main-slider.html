فیچر «بنر هدر» + «اسلایدر اصلی» در پنل ادمین

یک جدول مشترک site_banners (با ستون placement و تصویر دسکتاپ/موبایل) به‌علاوه‌ی جایگاه جدید main برای اسلایدرهای محصول: کامل‌ترین CRUD ممکن (مهاجرت goose، entity/repository/usecase/DTO/request، ۶ روت ادمین، ۳ تمپلیت، سایدبار، سیدر) و رندر استورفرانت با هندل کردنِ «بنر/اسلایدر نداریم» — یعنی وقتی داده‌ای نیست، بخش کلاً حذف می‌شود نه اینکه جای خالی بمونه.

۱. عنوان و خلاصه‌ی اجرایی

دو فیچر خواسته شد: (الف) بنر هدر — بنر بالای سایت (دو اسلات موبایل/دسکتاپ در home2) که از ادمین مدیریت بشه و اگر بنر فعالی نباشد، کلاً نمایش داده نشود؛ (ب) اسلایدر اصلی — بخش <div class="mainSlider mt-lg-5"> که به یک اسلایدر افقیِ کارت-محصولات (سبک دیجی‌کالا: تیتر + زیرعنوان + «مشاهده همه» + کارت‌های تخفیف‌دار) تبدیل بشه و دیتاش از ادمین بیاد.

اسکیمای انتخابی (با تأیید کاربر): یک جدول مشترک site_banners با ستون placement؛ اسلایدر اصلی هم از همان ماشین اسلایدر محصولات موجود (product_sliders + slider_products) با یک position جدید main و فیلد جدید subtitle ساخته شد — یعنی هیچ جدول یا کد تکراری تولید نشد و CRUD کاملِ اسلایدر (انتخاب محصول، بازه زمانی، وضعیت) از قبل موجود بود و فقط گسترش پیدا کرد.

۹. نکات آموزشی

  • الگوی CRUD در این ریپو ثابت است: entity ← repository interface (که requests و gin.Context را import می‌کند — عمدۀ بدهی این ریپو) ← GORM ← usecase نازک ← DTO با StatusText/Schedule فارسی ← request با اعتبارسنجی keyed ← هندلر با فلش session (errors/olds/message) ← ۶ روت POST/GET ← سایدبار + ActiveAdminMenu. هر فیچر جدید باید همه‌ی این ۱۰ نقطه را بزند وگرنه یا کامپایل نمی‌شود یا در رندر خاموش می‌شکند.
  • GORM و صفرها: ستون‌هایی که DEFAULT دارند (مثل status BOOLEAN DEFAULT TRUE) اگر در Create مقدار صفر بگیرند، GORM با tag/default جایگزین‌شان می‌کند → حتماً Select(...) بزنید (دقیقاً همان دلیلی که سیدر بنرها هم دارد).
  • map سطح-پکیج در هندلرها سم است: pkg/errors وضعیتش را بین درخواست‌ها نگه می‌دارد؛ هر جا errors.Get()[key] را به‌عنوان شرط خواندید، قبلش errors.Init() بزنید وگرنه خطای دیروزِ یوزر دیگری را به او نسبت می‌دهید.
  • «بنر نداریم» یعنی حذف، نه جای خالی: در template با {{if .HEADER_BANNER}} … {{end}} کل تگ بسته می‌شود؛ در هندلر یک nil پاس بدهید نه یک DTO صفر (چون {{if}} روی struct همیشه true است).
  • fallback تصویر موبایل را در DTO نگه دارید نه در قالب: یک متد کوچک مثل MobileSrc() (با value receiver تا در template map هم کار کند) از {{if}}/{{else}} تو در تو در ۲ جای قالب جلوگیری می‌کند.
  • افزودن enum به ستون بدون CHECK: اگر migration قبلی روی ستون شما CHECK نگذاشته، افزودن مقدار جدید فقط تغییر کد است؛ ولی حتماً با \d table در PostgreSQL چک کنید، نه با حدس زدن.
  • ایدمپوتنت‌بودن سیدر را سطح ردیف نگه دارید: بررسی «آیا کلاً چیزی سید شده؟» بعد از اولین اجرا هر افزوده‌ی آتی را برای همیشه می‌سوزاند؛ بررسی per-slug/per-key هم سازگار-رو-به-عقب است هم آینده‌نگر.
  • Swiper و کلاس‌های nav مشترک: کلاس عمومی .swiper-btn-next با document.querySelector توسط همه‌ی instanceها گرفته می‌شود؛ برای اسلایدر جدید کلاس اختصاصی (.mainSlider-products-next) تعریف کردم تا با شگفت‌انگیز/استوری/سرچ قاطی نشود.
  • تست دستیِ پنل ادمین: کوکی‌های Secure روی http ارسال نمی‌شوند؛ یا فلگ secure را در cookie-jar دستکاری کنید یا مستقیم -H "Cookie: session=…" بزنید.

۱۰. کارهای باقی‌مانده / ریسک‌ها

  • سرور شما باید ری‌استارت شود: پروسه‌ی در حال اجرا روی پورت 8010 از ساعت 01:19 کد Go قدیمی دارد؛ روت‌های /admins/site-banners و منطق جدید را ندارد (تمپلیت‌ها live خوانده می‌شوند ولی کد Go نه). کافی است Ctrl+C و دوباره go run . serve بزنید.
  • جایگاه placement='main' در جدول ساخته شده ولی هیچ خواننده‌ای ندارد (اسلایدر اصلی، محصولات است). اگر بعداً بنر تصویریِ اسلایدر اصلی خواستید، فقط کافی است همان CRUD را با فیلتر placement=main به صفحه‌ی home2 وصل کنید.
  • بنر هدر فقط در home2 رندر می‌شود چون هدرِ home.html (طراحی قدیمی) اسلات بنر ندارد. اگر هدر را یکی کردید، پارشال مشترک بسازید.
  • پسوند gif در AllowImageExtensions نیست؛ سیدر چون فایل را مستقیم کپی می‌کند top2.gif کار می‌کند، ولی اگر ادمین بخواهد همان را آپلود کند رد می‌شود. یا باید gif به whitelist اضافه شود یا تصویر را به webp تبدیل کرد.
  • پاک‌سازی سید: اگر بخواهید سید بنر هدر را دوباره اجرا کنید، باید ردیف‌های بنر سایت نمونه% را پاک کنید (idempotency بر اساس همین پیشوند است).
  • قالب‌های موجود لمس شدند: بر خلاف قاعده‌ی «تمپلیت‌ها frozen» در AGENTS.md، برای ساخت فیچر لازم بود sidebar.html و admin_slider_form.html ویرایش شوند (به دستور صریح شما). فایل‌های جدید اضافه شدند نه جایگزین.
  • بدون commit — هیچ چیزی stage/commit نشده است.
  • ریسک تست: تست‌های integration (با TEST_DATABASE_URL) اجرا نشدند چون متغیر تنظیم نشده؛ تست‌های واحد همه سبزند.
