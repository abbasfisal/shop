اصلاح home2.html و استاتیک‌های قالب جدید

مسیرهای نسبی CSS/JS/تصاویر صفحه‌ی /home2 به مسیر مطلق تبدیل شد، فولدر assets قالب دانلودی داخل public/ کپی شد تا با روت /assets سرو شود، و سه باگ ریز (تایتل، فایل غایب اسلایدر، یک URL相对 در JS) هم اصلاح گردید. صفحه با HTTP 200 و بدون هیچ asset گم‌شده‌ای بالا می‌آید.

۱. عنوان و خلاصه‌ی اجرایی

روت GET /home2 به هندلر HomePage2 و قالب templates/site/home2.html اضافه شده بود، اما این قالب مستقیماً از قالب آماده‌ی «Home6» (پروژه‌ی 279533) کپی شده بود و سه مشکل داشت:

  1. هر ۲۱۶ مرجع href="/assets/…" / src="assets/…" نسبی بودند (کار می‌کردند ولی در برابر trailing-slash و اِمبد شدن partial شکننده بودند).
  2. فولدر assets/ اصلاً داخل ریپو وجود نداشت → عملاً همه‌ی CSS/JS/تصاویر 404 می‌شدند و صفحه بی‌استایل بالا می‌آمد.
  3. یک تصویر اشتباه (mobile/7.webp به‌جای .gif)، تایتل هاردکد و یک URL نسبی داخل main.js.

راه‌حل: کپی css/js/fonts/images/video از پوشه‌ی دانلود به public/ (طبق قرارداد موجودِ /assets/shop → public/shop)، تبدیل همه‌ی مسیرها به مطلق، و اصلاح سه باگ ریز. تغییری در هندلر/روت لازم نبود.

۲. درخواست اصلی

r.GET("/", publicHdl.HomePage)
r.GET("/home2", publicHdl.HomePage2)
«یه homepage2 اضافه کردم که باید بری و home2.html رو اصلاح کنی مثلاً مسیر های css»

۳. زمینه و کشف

  • گراف: برای این تسک چون مستقیماً مسیر فایل مشخص بود، سراغ grepping رفتم نه graphify query (سوال درباره‌ی «مسیر فایل‌های استاتیک» است نه جریان داده بین لایه‌ها).
  • روت استاتیک: cmd/serve.go:119-122 — r.Static("/assets", filepath.Join(wd, "public")) یعنی /assets/X ⇔ public/X (پس /assets/css/a.css ⇔ public/css/a.css).
  • هندلر: interfaces/http/handlers/web/handlers.go:202 (HomePage2) — کپی از HomePage با نام تمپلیت home2.
  • روت: interfaces/http/routes/web_routes.go:47.
  • بارگذاری تمپلیت: interfaces/http/response/load.go:7 — LoadHTMLGlob("templates/*/*.html") → فایل جدید خودکار لود می‌شود، نیازی به رجیست دستی نیست.
  • منبع قالب: با جستجوی کلاس اختصاصی stories-Swiper در کل دیسک، منبع پیدا شد: ~/Downloads/279533-main-3.0.0/Home6&otherPages/ (فایل index.html همان home2.html است با دو خط {{define}} بیشتر).
  • مقایسه با home.html: صفحه‌ی اصلی از /assets/shop/css/main.css استفاده می‌کند و همه‌ی مسیرهایش مطلق‌اند — یعنی قرارداد پروژه از اول مطلق‌نویسی بوده است.
  • RTL: در style.css قاعده body { direction: rtl; } هست، پس تگ <html lang="en"> را دست نزدم (رفتار چیدمان از CSS می‌آید).

۴. تصمیم‌ها و چرایی (ADR-style)

ADR-1: فولدر assets قالب کجا کپی شود؟

گزینهتوضیحوضعیت
الف) ریشه‌ی public/ انتخاب‌شده کپی css/ js/ fonts/ images/ video/ داخل public/ → با همان روت فعلی /assets/… سرو می‌شوند؛ دقیقاً هم‌قیددادِ /assets/shop → public/shop که صفحه‌ی home.html الان استفاده می‌کند. هیچ تغییری در کد Go لازم نیست. ✅ پذیرفته
ب) public/assets/ چون /assets ← public، URL می‌شد /assets/assets/css/… (زشت) یا نیاز به روت جدید در cmd/serve.go داشت (پیچیدگی بی‌جهت + برخورد نام‌ها). ❌ رد
ج) فقط css/js/fonts صفحه بدون عکس بالا می‌آمد ولی ۲۰۵ تصویرِ طراحی (بنر، اسلایدر، دسته‌بندی) خالی می‌شد. ❌ رد — با اصرار کاربر بر «صفحه‌ی درست» ناسازگار بود
د) فقط مسیرها را اصلاح کن، فایل‌ها را نیاور مسیر درست می‌شد ولی همچنان 404 — عملاً هیچ مشکلی حل نمی‌شد. ❌ رد

ریسک پذیرفته‌شده: حدود ۲۹ مگابایت فایل باینری (عکس + ویدیو) به ریپو اضافه می‌شود. اگر نخواهید در git نگه‌شان دارید، می‌توان آن‌ها را به .gitignore اضافه کرد یا از آپلود/CDN سرو کرد.

ADR-2: نسبی یا مطلق؟

  • انتخاب: مطلق (/assets/…) برای هر ۲۱۶ مرجع.
  • دلیل: مرجع نسبی از /home2 به /assets/… resolve می‌شود ولی از /home2/ یا صفحه‌ی تودرتو به /home2/assets/… می‌شکند؛ ضمن اینکه قرارداد home.html هم مطلق است.
  • گزینه‌ی ردشده: افزودن <base href="/"> — کل خط تغییر کمتر بود اما روی <a href="#"> و فرم‌ها اثر جانبی دارد و باز هم فایل‌های غایب را حل نمی‌کرد.
  • ریسک: صفر — چون روت /assets از قبل ثابت است.

ADR-3: دست نزدن به داده‌های داینامیک (BANNERS / SLIDERS)

  • مشاهده: هندلر HomePage2 مقادیر BANNERS_TWO, BANNERS_FOUR, SLIDERS را پاس می‌دهد ولی قالب از آن‌ها استفاده‌ای نمی‌کند (همه‌چیز هاردکد از قالب دانلودی است).
  • تصمیم: در این تسک دست نزدم، چون درخواست فقط «اصلاح مسیرها» بود.
  • پیامد: بنرها/اسلایدرهای ادمین روی /home2 نمایش داده نمی‌شوند — در بخش «کارهای باقی‌مانده» ثبت شد.

ADR-4: تایتل و زبان

  • انتخاب: <title>{{.TITLE}}</title> (هندلر از قبل صفحه اصلی فروشگاه را پاس می‌دهد).
  • رد: تغییر lang="en" به fa + حذف direction:rtl از CSS — چیدمان قالب به قاعده‌ی body{direction:rtl} در style.css تکیه دارد؛ دست زدن به آن ریسک به‌هم‌ریختن layout دارد.

۹. نکات آموزشی

  • قرارداد استاتیک این پروژه: r.Static("/assets", "public") یعنی /assets/X ⇔ public/X. فایل جدید = کپی داخل public/، نه داخل یک زیرفولدر assets (اگر public/assets/ بگذاری URL می‌شود /assets/assets/…).
  • URL در HTML نسبی به صفحه است، URL در CSS نسبی به فایل CSS است. url(assets/x.svg) داخل /assets/css/style.css می‌شود /assets/css/assets/x.svg — حتماً ../ بزنید.
  • URL در JS نسبی به سند (document) است، نه به فایل JS — پس "assets/images/…" در main.js از /home2 درست resolve می‌شد، اما برای یکدستی و ایمنی مطلقش کردیم.
  • تمپلیت‌های Gin با Glob سر استارت لود می‌شوند (LoadHTMLGlob("templates/*/*.html")): اسم {{define "home2"}} باید دقیقاً با سومین آرگومان CustomerRender(c, 200, "home2", …) یکی باشد؛ فایل جدید نیازی به رجیست دستی ندارد ولی تغییرش نیاز به ری‌استارت دارد (در اینجا air hot-reload داشت).
  • قالب دانلودی را هرگز کورکورانه کپی نکنید: اول منبع را پیدا کنید (grep -rl "<کلاس_اختصاصی>" /home/…) تا بدانید کدام فایل‌ها همراهش می‌آیند و کدام پسوندها واقعاً وجود دارند (7.gif vs 7.webp).
  • «صفحه بالا می‌آید» ≠ «درست است»: 200 برای HTML هیچ تضمینی برای CSS/JS نمی‌دهد؛ بعد از هر تغییر مسیر، حداقل یک بررسی سیستماتیک روی همه‌ی مراجع خروجی بگیرید (اینجا: استخراج با grep + چک وجود فایل).
  • قالب‌های templates/ در این ریپو «frozen» هستن (AGENTS.md) — این تغییر با اصرار مستقیم کاربر روی فایل جدید home2.html انجام شد؛ برای قالب‌های قدیمی اول بپرسید.
  • گذاشتن فایل باینری در git: ۲۹MB عکس/ویدیو هزینه‌ی ریپو دارد؛ اگر لازم نیست .gitignore کنید یا به آپلود/CDN منتقل کنید.

۱۰. کارهای باقی‌مانده / ریسک‌ها

  • داده‌های داینامیک: قالب از BANNERS_TWO, BANNERS_FOUR, SLIDERS استفاده نمی‌کند → بنر/اسلایدر ادمین روی /home2 دیده نمی‌شود. باید بخش‌های هاردکد را با {{range .SLIDERS.…}} و {{range .BANNERS_TWO.Data}} جایگزین کرد (مسیر تصویر از .BANNER_PATH / .MEDIA_PATH می‌آید).
  • لینک‌ها: تقریباً همه‌ی <a>‌ها href="#" هستند — مسیرهای واقعی routes (دسته‌بندی، محصول، سبد خرید، ورود) باید وصل شوند.
  • تکرار کد: HomePage2 عیناً HomePage است؛ می‌شود یک متد مشترک ساخت و فقط نام تمپلیت را پارامتری کرد.
  • پوشه‌ی scss: عمداً کپی نشد (فقط منبع کامپایل است، استفاده‌ای ندارد).
  • committed نشده: هیچ چیزی را commit نکردم؛ git status → ۲ فایل modified (هندلر/روتِ کاربر) + ۱ تمپلیت + ۵ فولدر جدید public/.
  • assets ناخواسته: پوشه‌های images/product/300/* و mainSlider عکس‌های نمونه‌ی قالب‌اند؛ در آینده باید از uploads/ و دیتابیس بیان.
  • سرور در حال اجرا: پروسه‌ی shop روی پورت 8010 از قبل بالا بود (با air). اگر جای دیگری اجرا می‌کنید، ری‌استارت لازم است.
